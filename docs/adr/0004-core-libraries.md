# 0004 – Core libraries: Room, Koin, Navigation Compose

- **Status:** Accepted
- **Date:** 2026-10-16

## Context

The MVP needs local persistence, dependency injection, navigation between screens and a small
key-value store (e.g. "onboarding seen"). All of it must work in `commonMain` for Android and iOS.
Firebase (accounts, sharing) and crash reporting are planned later.

## Decision

| Need | Library | Rejected alternatives |
|---|---|---|
| Database | Room KMP with `sqlite-bundled` (code generated by KSP) | SQLDelight: mature in KMP, but less familiar to Android reviewers and needs hand-written SQL for every query |
| Dependency injection | Koin (via BOM) | Manual DI: fine at first, but grows with every ViewModel; Kotlin Inject: compile-time safety, less KMP tooling |
| Navigation | JetBrains Navigation Compose with type-safe `@Serializable` routes | Voyager: slower development, non-standard API |
| Key-value settings | multiplatform-settings (no-arg) | DataStore: heavier for a single flag |
| Test helpers | kotlinx-coroutines-test, Turbine, AssertK, koin-test | – |

Not added because the app does not need them: networking (Ktor), image loading (Coil), maps,
location, permissions, biometrics, encryption.

## Consequences

- Room and Koin are behind the repository interfaces from [ADR 0003](0003-uuid-ids-and-repository-interfaces.md),
  so a Firebase-backed repository can be added later without touching the UI.
- KSP runs Room's compiler for every target (`kspAndroid`, `kspIosArm64`, `kspIosSimulatorArm64`);
  schemas are exported to `shared/schemas/` and committed, so migrations can be tested.
